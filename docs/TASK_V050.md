# Astrspire v0.5.0 实施记录

## 已批准范围（2026-10-23）

以 VOFA+ 1.3.10 的已有静态证据、用户截图和配置为参照，完善日常使用闭环，不宣称完整等效。本轮不扩展 STC 芯片，不增加 STM32 烧录界面。旧产物和旧报告保留。

## 架构与顺序

1. **P0 数据可靠性**：先用失败测试复现长历史换算缩短、CSV 时间丢失；建立有界 `SampleStore` / `SampleFrame`，原始值不受显示换算影响；区分接收字节、解析、保留、淘汰、绘图省略及异常丢弃；记录写入独立线程，有界队列失败明确收口。
2. **P1 页面与命令**：用户页面可新增、命名、复制、排序、删除，混合卡片；稳定页面/卡片/命令组 ID；共享采集、采样与图像存储；组内发送冻结快照；破坏性配置操作确认数量与恢复方式。
3. **P2 保存与导入**：schema5，兼容 schema1–4，迁移旧四页与命令；原生导入纯检查、映射预览、显式应用，未知类型/编码及畸形节点有字段路径，不猜测无非空证据的结构，导入绝不连接/发送/读取模型。
4. **P3 Demo**：保留逐行矩阵，增加 CSV 整文件与 JPG 单图独立周期、启用、循环、暂停的并行模式；自然排序、严格数字检查，同一解码链，不发送设备。
5. **验收与交付**：先离线软件测试，再独立三板检查；交付源码、onefile/onedir、功能矩阵、当前测试与三板分别记录。

## 设备操作约束

- STM32 刷写前重新确认探针、芯片和串口，完整备份当前 Flash；备份失败或读保护即停止，不解保护，不强擦。先 60 秒，再 10 分钟，帧序号检查丢失/重复/乱序；恢复并校验后才结束。
- F103 旧原程序此前已丢失，本轮不能找回；只备份并恢复本轮开始时程序。G431 使用独立 HAL 测试工程、USART1 PA9/PA10，不修改用户原工程。
- STC 仅 F002 / `66 43 FD`。无可靠回读则必须确认当前程序对应恢复 HEX，否则只识别、不擦写；不写 EEPROM/选项，不控制供电。
- 缺板、缺线、缺恢复来源如实记为未完成；恢复失败立即报告并停止后续刷写。普通自动化测试不得触碰硬件。
- 所有可控缓存、临时文件、备份、证据与交付在 F 盘任务目录。
