## v0.4.0 数据区补充

- 数据引擎扩展是自有声明式JSON，最多32个；不执行原生DLL/QML/Python或下载插件。扩展/主题冲突拒绝载入，不静默覆盖。
- schema4工作区保存命令、控件、自由布局、引擎、主题和参数，不保存或恢复连接、发送/录制任务、编辑布局状态。载入会替换未保存命令/控件时先确认。
- 自由布局仅显式编辑时开放拖动/拉伸；此时禁用控件发送。布局取消、失焦、隐藏和删除不会补发松开命令；不能保证外部设备因此进入某种安全状态。
- 图像封装按N有界读取，索引0–15、payload8MiB、实际图像1600万像素、缓存32MiB；这些是本软件限制，不是官方最大值。原始Qt格式是未实测兼容假设。SVG只支持受限静态子集，不加载外链；GIF只读首帧。
- 图像效果仅用于显示；编码图保存源字节，raw图保存当前显示PNG。新增CPU效果缩小预览，不能伪装为全分辨率原始图；原载荷可单独导出。图像/分析/文本导出均拒绝覆盖现有文件。
- JSONL记录只在用户显式开启后写入，保留RX/TX原始字节；最大128MiB。离线回放仅重解码RX，绝不执行TX记录或连接设备。CSV矩阵和图像目录也是本地来源。
- 显示比例/偏移仅影响绘图、统计和控件反馈，不修改原始记录。FFT假设等间隔并使用设定Δt，不是设备采样率验证。软件到达速率不等于物理链路时钟。
- 本轮没有启动原软件、连接板卡、做新抓包或扩大烧录指纹；REA只读分析的工作会话已保存关闭。所有分析快照继续留在private，不捆入EXE。

## ISP 写入门禁

- 通用 `HARDWARE_DIALECTS` 保持为空；另设严格指纹注册表 `ACCEPTED_HARDWARE_PROFILES`，当前只有 F002 / `66 43 FD`（6.6C）。界面真实烧录入口只对该指纹开放，且必须满足：已选串口、型号 STC89C52RC/LE52RC、已载入 HEX。**2026-10-21 用户明确要求移除风险勾选和擦除确认弹窗，因此当前是一键启动**；点击即进入擦除流程，误触会覆盖芯片程序。
- 下载核在擦除前再次校验芯片 ID、Bootloader 原始字段、注册指纹、HEX 范围和 purge 能力；任一不匹配都在协商/擦除前停止。块 ACK 不是全片回读，`FF/82` 没有已知结束 ACK；失败后不自动重试，程序可能不完整，要求断电重启并用官方工具恢复。
- 模拟会话只使用 `SIM/` 载荷和内存中的 `SimulatedTransport`。显示的芯片识别、擦除、写入、确认和进度都是演示事件，不代表设备响应。
- 官方会话离线回放使用已核对的历史帧，先核对原始记录身份、芯片/版本、HEX 和全部应答。回放不导入或打开真实串口，结束文案明确标记离线。原始记录与精确 golden 含设备特有字段，保存在忽略目录，不打入 EXE；公开测试夹具已脱敏并标注修改范围。
- AiCube v6.97A 的芯片条目、命令与布局只有逐项静态证据时才进入候选目录。目录条目不等于支持烧录；缺失的芯片 ID、Bootloader 版本、参数和 ACK 不得推测填充。
- 除 F002 / `66 43 FD` 外，其他芯片与协议族没有真实下载注册；不得继承 STC89 的识别偏移、sum8、8 KiB 或 128 字节块规则。
- 新只读识别手选 COM 后点击独立按钮；只发送 `7F`，最多等待 30 秒，解析后关闭串口。主界面默认真实模式，模拟入口移到工具菜单；风险勾选已于 2026-10-21 按用户要求移除。打开端口仍可能改变 DTR/RTS。不发送协商、擦写、选项或结束复位命令；未知身份仅显示不支持烧录。识别成功不等于烧录成功。

## VOFA 风格监视

- 串口枚举只读取系统设备元数据。数据监视必须由用户显式选择 COM 口和波特率并点击连接；导入工作区不自动连接。
- 连接本身不发送数据；用户显式点击发送/回车或打开周期发送后，数据才进入有界队列，由同一工作线程写入。周期默认关闭，断开/错误/导入工作区后不恢复；停止时清除未发送队列。`TX 已交驱动` 只表示整包写操作完成，不证明设备接收或执行；失败写入的字节数可能未知，不自动重试。
- 同一进程内使用 `PortLeaseManager` 防止数据监视与只读 ISP 同时占用同一 COM；其他进程占用仍由操作系统/驱动处理。租约取得后才打开，关闭后才释放。
- **打开串口并不保证电气上完全被动**：USB 转串口驱动可能在打开时改变 DTR/RTS 电平。用户连接有复位、供电或敏感外设的板卡前应自行确认接线与驱动行为。本轮未打开 COM 口进行验证。
- GUI 支持显式开启实时 CSV 和导出最近采样，两者均拒绝覆盖已有文件；停止/断开/关闭会回收记录流。合成演示的记录来源在日志中标明，CSV 时间是软件接收时间。暂停只冻结显示，不停止采集或记录。
- JSON 工作区只保存设置，包含发送文本但不保存/恢复周期启用状态，不兼容或冒充 VOFA+ 原生工程格式。
- TCP 客户端、单连接服务器与 UDP 只在显式开始后创建/连接/绑定 socket；TCP 连接存在系统协议流量，但不会自动发送用户应用载荷。UDP 无显式对端时只接收，不依据来包自动学习发送目标。
- 长格式CSV回放、数值矩阵CSV、图像目录及原始记录回放均不连接设备或发送数据。回放进度是本地读取/播放进度，不是设备操作进度。波形暂停与来源暂停是不同动作。
- 文件与命令顺序发送只有用户显式开始后才启动 QTimer。文件按原始字节发送，不识别或执行 ISP；文件最大16MiB，默认每20ms入队1024字节，队列拒绝或断线即停止不重试。序列使用开始时的命令快照，运行期间不与手动/周期发送交错。
- 发送任务进度仅统计入队；正常完成不清队尾，显式取消/断开会丢弃待发队列，但已交驱动的字节不能撤回。`已入队100%` 不代表对端全部接收，更不代表烧录成功。
- 工作区、命令、控件 JSON 为三个独立自有格式；导入均不自动连接、开始任务或恢复周期。日志写可执行文件旁的 `logs/`（源码运行时项目根 logs），无可写目录时仍保留界面日志。
- HEX/BIN 和 EEPROM 缓冲区查看/导出只有文件副作用；不会写设备。BIN 导出最低地址是基址，空洞补 FF、跨度至多 8 MiB；导出拒绝覆盖。EEPROM 的实际布局/写法未启用。
