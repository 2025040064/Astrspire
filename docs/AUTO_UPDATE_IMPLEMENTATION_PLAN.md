## 一、已确认现状与技术选择

当前工程为 Python 3.12、PySide6、PyInstaller，已有单文件和目录版，但没有安装器、自动更新模块或发布仓库配置。检查时应用版本为 `0.6.0.dev4`。

实际影响：

- 自动日志位于 EXE 旁，不能直接覆盖程序目录。
- 工作区采用 schema8，由用户选择路径保存；没有发现数据库。
- 工作区及发送历史主要保存在内存中，现有退出流程没有保存确认。
- 正常关闭可能因记录或线程尚未结束而拒绝退出。
- 单文件解包、部分运行输出使用开发机绝对路径，不适合正式安装版。

采用已确认的方案：

- **PyInstaller onedir＋Inno Setup＋独立更新助手**。
- 发布仓库规划为 **2025040064/Astrspire-Releases**。
- 使用免费 **Ed25519 公钥签名**，不购买 Windows 代码签名证书。
- 首个安装版定为 `0.7.0`，首次升级测试使用 `0.7.0 → 0.7.1`。
- 首版支持 Windows 10/11 x64，仅整包更新，不做差分。

不采用 Velopack 的原因是其默认更新行为可能结束占用程序目录的进程，与本项目禁止强杀业务进程的要求冲突。[Velopack 官方说明](https://docs.velopack.io/packaging/operating-systems/windows)

本轮保持现有白蓝界面，不应用附件 design.md 的其他页面风格，不改串口、烧录、波形和协议业务。

## 二、安装布局与数据保护

### 安装与更新布局

程序安装至 `%LOCALAPPDATA%\Programs\Astrspire`，采用用户级安装，不请求管理员权限。

采用“稳定启动入口＋版本目录”：

- 桌面快捷方式始终指向稳定启动入口。
- 每次更新安装到独立的版本目录，不覆盖正在使用的旧版本。
- 通过原子写入的活动版本记录决定启动哪个版本。
- 保留当前版本和上一个确认可用版本，失败时切回旧版本。
- 更新助手在程序目录之外运行，不覆盖自身。

安装器明确设置：

- `PrivilegesRequired=lowest`
- `CloseApplications=no`
- `RestartApplications=no`
- 使用 `AppMutex`、安装互斥锁阻止运行期间安装，不调用强杀接口。

依据：[Inno Setup 权限说明](https://jrsoftware.org/ishelp/topic_setup_privilegesrequired.htm)、[进程占用检查](https://jrsoftware.org/ishelp/topic_setup_appmutex.htm)、[CloseApplications](https://jrsoftware.org/ishelp/topic_setup_closeapplications.htm)。

### 数据位置与旧版处理

- 更新偏好、工作区恢复文件、发送历史：`%APPDATA%\Astrspire`。
- 日志、下载、更新事务和恢复资料：`%LOCALAPPDATA%\Astrspire`。
- 用户选择保存的工作区、CSV、JSONL、固件和其他文件保持原路径，不自动搬迁、不改格式。
- 工作区继续使用 schema8，更新功能不升级业务数据格式。
- 旧便携 EXE 和目录保留，提供一次性安装新版的路径；不能远程升级没有更新代码的历史程序。
- 如用户选择导入旧目录，只复制明确识别的配置和日志，生成校验清单，原文件不删除；不扫描整盘。

按已确认的保留范围，更新前保存当前工作区和20条发送历史。未记录的波形、报文及图像缓存不承诺跨重启恢复；存在未导出数据时提示“先导出／继续更新／取消”。

恢复工作区只恢复配置，不连接设备、不恢复周期发送、不执行烧录。

## 三、更新模块与安全流程

### 最小接口与界面接入

新增独立更新模块，主要接口为：

- `UpdateController`：检查、下载、取消、跳过版本及更新状态通知。
- `VerifiedUpdate`：通过签名、版本、大小与哈希验证的更新对象；安装入口只接受该对象。
- `UpdateCoordinator`：保存状态、多实例协调、正常退出、安装与恢复。

沿用 Qt 工作线程和信号更新界面，不在主线程联网。仅增加现有菜单中的“检查更新”、更新设置、进度及更新说明对话框，不重排主窗口。

默认设置：

- 自动检查开启，主窗口显示后异步检查，每24小时一次。
- 自动下载关闭，可由用户开启。
- 稳定版排除草稿和预发布版本。
- 跳过版本只影响自动提示，手动检查仍可查看。
- 未配置发布仓库或可信公钥时，显示未配置，不尝试安装。

### 匿名检查与下载

读取固定仓库的正式版接口：

```text
https://api.github.com/repos/2025040064/Astrspire-Releases/releases/latest
```

普通用户无需账号和 Token。公开 Releases 支持匿名读取。[GitHub 官方接口说明](https://docs.github.com/en/rest/releases/releases#get-the-latest-release)

实现要求：

- 使用 HTTPS，保持正常证书校验。
- 缓存 ETag，处理304、403、429及服务器退避要求。
- 连接超时5秒、读取超时15秒，最多两次退避重试；失败不阻塞启动。
- 稳定版仅接受有效的三段版本号，按数字比较，不做字符串比较。
- 下载写入 `.partial`，显示字节数和进度，可取消、失败后重新下载。
- 下载前及安装前检查空间，覆盖安装包、解包、新版本目录和恢复资料需求。
- 仅允许固定仓库的 Release 资产及 GitHub 官方 HTTPS 重定向，不执行任意 URL。

### 发布者与完整性验证

每个版本发布：

- `Astrspire-<version>-win-x64-Setup.exe`
- `update-win-x64.json`
- `update-win-x64.sig`
- 对应源码包、构建清单和更新说明。

签名清单绑定应用标识、版本、stable通道、win-x64、安装包名称、大小、SHA-256、内容清单哈希及最低更新助手版本。

使用 `cryptography` 的 Ed25519 实现，不自行编写密码算法。[官方签名接口](https://cryptography.io/en/latest/hazmat/primitives/asymmetric/ed25519/)

验证顺序固定为：

1. 使用客户端内置可信公钥验证清单原始字节。
2. 验证清单结构、目标应用、版本和平台。
3. 验证下载文件大小及SHA-256。
4. 更新助手在执行安装器前再次验证。

私钥只存在可信发布环境中，不进入源码、客户端、日志或源码包。客户端不接受网络提供的新公钥作为信任依据。

免费签名验证的是发布密钥身份，**不能消除 SmartScreen 提示，也不能让 Windows 显示已验证的证书发布者**。首次安装包仍须从确认的官方发布地址取得。

### 正常退出、安装与恢复

更新下载完成后提供：

- **立即重启更新**：保存状态，正常退出，安装完成后重启。
- **稍后更新**：继续使用，在正常退出时安装，不自动重启。
- **取消安装安排**：保留已验证下载，暂不安装。

必须满足以下门禁：

- STC擦写进行中只允许检查和下载，禁止更新触发关闭或取消会话。
- 更新重启先保存工作区和发送历史；失败或取消则不退出。
- 多实例保持可用，但安装必须等待同一安装的全部实例及相关子进程正常退出。
- 不把 `close()` 调用成功当作进程已退出，不调用 `taskkill` 或 `TerminateProcess`。
- 新实例启动遇到更新事务时显示等待状态，不进入业务模块。

助手记录可恢复的更新事务，安装新版本后校验文件和目标版本，执行不连接设备的启动健康检查。检查通过后才切换活动版本。

安装失败或健康检查失败时，旧活动版本保持不变。断电或助手退出后，下一次启动先检查未完成事务，再继续或恢复。健康检查进程未正常退出时不强杀、不提交新版本，保留恢复入口和明确错误信息。

## 四、构建、发布与文档交付

### 构建与兼容调整

- 保留旧单文件和目录便携构建，新增正式安装渠道。
- 正式安装渠道只使用 onedir，不包含开发机 F/D 盘绝对路径。
- 将版本来源集中到应用版本定义，构建名、安装器、Windows版本资源、更新清单和Tag由此生成并校验。
- 初始构建工具采用 Inno Setup 6.7.3；新增 `cryptography==50.0.2`，先验证 Python3.12 Windows wheel，再更新依赖锁。兼容失败时停止，不静默换版本。
- 开发机上的构建、测试和证据放F盘；终端用户使用各自的Windows用户目录。
- 更新助手和启动器协议在首版固定；遇到不支持的最低助手版本时转人工安装，不冒险自动执行。

实施时先将本方案和技术栈影响写入 `docs/AUTO_UPDATE.md`，再修改代码。另交付：

- `docs/RELEASE_GUIDE.md`：密钥保管、构建、签名、发布和恢复步骤。
- `docs/UPDATE_TEST_REPORT.md`：实际命令、环境、产物哈希及通过／失败／未执行结果。

### 发布顺序

版本修改 → 完整回归 → 构建 onedir、助手和安装器 → 安装及升级测试 → 生成清单并签名 → 验证签名 → 创建Release草稿 → 上传全部资产 → 匿名下载复核 → 获准后转为正式发布。

正式Tag、安装器、清单和应用版本必须一致。构建清单绑定源码快照SHA-256、依赖锁、工具版本和产物哈希，不能使用来源不明的旧EXE发布。

发布脚本默认只构建和验证；创建仓库、上传以及正式发布需明确授权。发布凭据只存在开发者环境，不进入客户端。

### 正式发布前门禁

- 现有SerialWeb移植包含AGPL义务，Release必须提供相应完整对应源码和构建材料，不能仅发布二进制。
- 保留Lissio及其他依赖许可。
- 随包字体目前缺少本地授权材料；未确认授权前阻止正式公开发布，不擅自删除或替换。
- 默认按当前个人项目使用规划；若转商业用途，另核对安装器及全部资源的许可要求。

依据：[Inno Setup 官方发布与许可说明](https://jrsoftware.org/isdl.php)。

## 五、测试与完成标准

先写失败测试，再接入最小实现。普通测试不连接串口、不操作板卡。

必须覆盖：

- 版本相同、发现新版、预发布过滤、跳过版本及手动检查。
- 匿名访问、离线、GitHub限流、超时、取消、下载重试和空间不足。
- 安装包损坏、错误签名、未知公钥、清单与资产不一致、错误平台和降级请求。
- 工作区保存取消／失败、记录线程收尾、STC忙碌、多实例和新实例启动竞争。
- 首次安装、连续升级、重复安装、文件锁定、安装失败、启动失败及事务中断后的恢复。
- 升级前后工作区和发送历史一致；外部CSV、JSONL等用户文件哈希不变。
- 旧版本可启动；恢复后不自动连接、发送或烧录。
- Windows10/11普通用户环境、中文路径、空格路径及完整业务回归。

执行层次为：离线单元测试 → 本地安装升级测试 → 干净Windows环境 → 获准后的公开仓库匿名端到端测试。每一层单独留证，缺环境时明确标记未执行。

计划制定时仅完成只读工程检查、方案选型和官方资料核对，**尚未实现或实测自动更新**；不能把此前874项业务测试算作更新系统验收。联网试探已遇到GitHub限流和PyPI超时，实施时必须验证这些情况下仍可正常离线启动。

完成标准是：普通用户无需GitHub账号，更新来源和包均可验证；业务正常退出后才安装；失败可继续使用旧版；原有用户文件不受破坏；未经批准不修改无关功能。
