# Astrspire dev4 使用说明

## 串口收发

1. 在数据页选择串口，输入固件实际波特率。可按COM、设备名称、VID:PID筛选列表；筛选不改变已选端口。
2. 选择数据引擎和串口参数。新增RTS/CTS、XON/XOFF；无流控仍是默认值。DTR/RTS只在本次连接前设置，载入工程或应用预设会关闭，不自动连接。
3. RX文本编码在接收菜单，TX编码在发送框右侧，互不影响。旧命令和控件默认仍为UTF-8，新建命令可选择编码，控件属性也可设置发送编码。
4. 发送前查看实际字节数、HEX及结束符。支持无、LF、CRLF、CR、TAB。文本结束符使用所选编码；HEX结束符为直接字节。
5. HEX支持 AA 01、AA01、0xAA,0x01、\xAA\x01，以及空白、逗号、冒号、分号、竖线分隔。奇数位和非法内容整体拒绝，不跳过错误继续发送。

“历史”保留本次运行中最近20条驱动完成的手动发送，去重后最近在前。回填不会发送，周期发送不刷历史。驱动写入完成不等于设备收到或执行；失败/取消不记成功。

## 报文与协议工作台

点击数据页“报文 / 协议…”或工具菜单入口。窗口可自由拉伸，三个页分别为原始报文、协议与命令模板、连接预设。

### 原始报文

- 共享缓存最多10000块或16MiB。方向、软件时间、独立RX/TX流偏移、HEX/ASCII并排显示。块来自读取/完成事件，不等同协议帧。
- 选中后下方显示完整块的字节偏移；复制HEX不会插入显示折行。导出只写明确选中的同方向字节，不覆盖已有文件。
- 上滚停止本视图追底；采集、记录和发送继续。点击“返回最新”退出搜索/快照。
- 搜索支持文本、HEX、字节正则，可跨连续读取块，但不混合方向；文本按当前接收编码转换。最多1000个结果。
- 正则匹配字节，不是Unicode字符；在独立进程限时运行，超时可取消。显示过滤和历史淘汰不改变采样或磁盘记录。
- “搜索记录…”显式读取旧JSONL或会话清单。文件流式搜索、结果有界；正则按1MiB窗口、每方向64KiB重叠，不保证任意长跨窗表达式。达到结果上限会明确标记未扫描全部。

### 协议与命令模板

左侧编辑声明式JSON，右侧输入发送参数和波形字段。支持帧头、长度、消息ID、数值、bytes/text、位域、条件字段、校验及帧尾，不执行Python/JavaScript。

示例：

    {
      "header_hex": "AA",
      "tail_hex": "55",
      "fields": [
        {"id": "size", "type": "length", "width": 1, "length_of": "data"},
        {"id": "data", "type": "bytes", "length_from": "size"},
        {"id": "value", "type": "uint16", "endian": "little"}
      ],
      "checksum": {"algorithm": "sum8", "start": 0, "end": "checksum"}
    }

参数 {"data":"10 20","value":4660} 生成 AA 02 10 20 34 12 22 55，波形字段填写 value。

- 数值：int8/uint8/int16/uint16/int32/uint32/float32/float64；整数ID和Length宽度1–8字节。
- bytes/text可用固定width，或引用前面的length_from。Length的length_of指定发送长度目标；length_mode为frame时表示全帧字节数。adjustment为明确的长度修正，解码加上、编码减去。
- 条件字段使用 when: {"id":"message_id","equals":1}，仅引用前面的ID。
- 位域type为bits，width为容器字节数，bits列出id、offset、length和可选signed。offset从字节流最高位起算，与普通数字端序无关；发送参数填写整个容器整数。
- 最多64字段、16KiB/帧、16个波形通道。不支持的布局或配置返回字段路径错误，不静默忽略。
- 校验支持none/sum8/sum16le/sum16be/xor8/lrc/crc8-smbus/crc16-modbus/crc16-ccitt-false/crc32-iso-hdlc。start/end为从帧首起算的左闭右开字节范围，end为checksum表示校验字节之前；byte_order为default/little/big。
- 默认CRC线上字节序：Modbus低字节先、CCITT-FALSE高字节先、CRC32低字节先。标准输入123456789分别得到37 4B、29 B1、26 39 F4 CB；CRC8为F4。

“离线解析”只解析输入HEX。“预览500ms RX”只复制已经打开源的最多4KiB，使用私有解析器，不污染正式解析；最多返回256帧。噪声、尾随半帧、截断和窗口缺失分别显示。坏校验只进入诊断，不进入有效采样。

“应用为解析引擎”须先停止当前源；只注册配置，不自动连接。同ID不同配置不覆盖，可改用新ID或在扩展管理中移除旧配置。

“生成发送字节”不发送。“填入发送框”仍须回主窗口手动发送。“加入当前命令组”保存字节快照，后续修改模板不改变已加入命令；本版没有动态自动应答或值变化自动发送。

协议/参数草稿、预设编辑支持200步撤销重做，连续输入合并；撤销不执行设备动作。草稿导入导出不连接或发送。已应用引擎不是草稿撤销的隐式副作用，修改后需明确再次应用。

### 连接预设

保存当前参数后，预设随工作区保存。可搜索、删除并撤销删除。“填入选中预设”只改表单，端口不在列表时留空，需用户重新选择；不会猜测另一COM或恢复连接。

## 记录与工程

原始RX/TX记录继续走独立写线程，每128MiB创建新分卷。第一卷保留原选定JSONL文件名，后续为.part0002等；同目录生成.session.json会话清单，包含分卷数量、大小和SHA-256。停止完成后可选择会话清单连续回放；旧JSONL仍能读。回放只解析RX，绝不重发TX。

文本日志每16MiB分卷。磁盘满、文件名冲突、队列满等错误停止对应记录并报告未保存数量，界面采集不因此冻结。不覆盖或自动删除旧记录；未正常结束会话可显式检查已有分卷，不冒充完整记录。

工作区写schema8，读取schema1–7；命令文件写schema2、读取schema1。旧工程手动发送沿用原RX编码值迁移，旧命令/控件保持UTF-8，避免改变原字节。工程载入不连接、不发送、不读取外部清单，全区擦除选项不保存。新工程不能保证旧软件读取，请另存文件保留旧版。

## STC 8KiB用户程序区擦除

仅限 STC89C52RC/LE52RC，且实际状态包严格匹配F002 / 66 43 FD。

- “擦除8KiB程序区…”无需HEX：点击后等待最长30秒，手动断电再上电，识别通过后才请求擦除0x0000–0x1FFF。
- “下载前擦除全部8KiB”只影响本次下载的擦除范围，不扩大HEX写块数量。默认关闭，操作后、换端口/芯片/模式或载入工程会关闭。
- 断电时无法擦Flash。“上电前”仅表示预先启动等待，不是软件启动或连接COM就自动擦除。
- 不修改EEPROM、ISP、选项或供电控制。仅擦除收到合法ACK后关闭端口，不发送未经仅擦除会话确认的FF/82结束序列，需手动重新上电。
- 2026-10-27实板复测：独立8KiB程序区擦除ACK匹配；全区预擦后21字节led.hex按既有协议填充为512字节、4个块ACK全部匹配。ACK不是空白回读，不宣称已逐字节验证为空。擦除后失败或取消不自动重试。

普通测试不打开板卡端口。用户本轮另行授权实板擦写后，重新枚举COM10为CH340，再严格匹配F002 / 66 43 FD完成上述两项实验。原始证据保留在captures/private，不分发设备标识。最终板上为最小LED程序，运行观察尚未完成。
