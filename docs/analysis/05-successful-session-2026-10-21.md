## 离线核对结果

- 从接收分片重组出 13 个完整 RX 帧，14 个 TX 帧均为完整 API 写入。
- 27 个帧全部通过当前纯编解码器的长度、大端长度字段、方向、尾 `16` 和 8 位累加校验核对；16 位校验分支不是本次采用的方言。
- 完成的写入 API 计数与抓取字节数一致，没有截断、脚本错误、缺失钩子或待完成 I/O 事件。
- 4 个数据块覆盖全部 HEX 数据；逐字节填充与 4 个写 ACK 数据和全部一致。
- 本轮重跑帧与状态机相关测试：`python -m pytest tests/test_framing_session.py -q`，13 项通过。另将同一抓包与不同的 `flashled.hex` 对照，分析器按预期拒绝数据不匹配；没有生成额外硬件通信。
- `CreateFileA` 转调 `CreateFileW` 导致相同句柄出现两条 OPEN 观察，不视为两条独立下载会话。
- 没有独立的全片回读校验或断电重启程序运行证据。块 ACK、Intel HEX 行校验、ISP 帧校验和全片回读是不同证据。

## 对之前失败的修正

旧失败会话的 DCB 请求是 2400 / 8E1，本次成功会话为 8N1。旧界面虽然显示 STC89 型号文字，硬件选项面板仍呈现 STC8 类配置；首次通过编辑组合框文本设置型号，可能没有触发官方内部的型号选择流程。这是有界面与配置差异支撑的推断，尚未作专门复现实验，不能认定唯一根因，也不能把旧失败归因于用户供电或接线错误。

今后应以实际选中项目、型号对应选项面板及 DCB 请求共同核对目标配置。
