## `f0` 位布局（代码确认）

`FUN_0043dfc0` 命中记录后：

- `class = (f0 >> 15) & 0xFF`（也写作 `f0 & 0x7F8000`），用于 `FUN_00447600` 的协议族 switch 与 `FUN_0043d530` 的时钟范围。
- `[+0x1a4] = (f0 >> 6) & 7`。
- `[+0x1a8] = (f0 >> 9) & 7`。
- 低 6 位含选项/能力标志：`FUN_0044e310` 检查 `f0 & 8`、`f0 & 0x20`；`FUN_0043dfc0` 用 `class` 与 `[+0x1a4]` 设置 `[+0x114] = 0x40/0x80`。

STC89C52RC/LE52RC：`f0=0x8607` → class 1、`[+0x1a4]=0`、`[+0x1a8]=3`、低标志 `0x07`。

> 注意：旧文档中的“家族 1、定时器类别 3、sum8 UART 类别 0”与这里的位位置存在标签歧义。本文只声明代码实际取出的位；不把旧标签当作已验证事实。

## 协议族选择

`FUN_00447600` 的 switch 直接使用 `class`：

- class 1–5、0x0F、0x10 → `FUN_00444110`
- class 6 → `FUN_00444050`
- class 7–9、0x11–0x13 → `FUN_004442e0`
- class 10、0x14 → `FUN_004445a0`
- class 0x0B–0x0E、0x15–0x18 → `FUN_00444870`
- class 0x19、0x1C → `FUN_00444d50`
- class 0x1A–0x1B、0x1D–0x2B → `FUN_00445100`
- class 0x2D–0x34 → `FUN_00445b80`
- class 0x3D、0x56、0x57、0x5A → `FUN_00446640`
- class 0x46 → `FUN_00446d70`
- class 0x4C、0x4F、0x54、0x58、0x59 → `FUN_00447040`
- 默认 → `FUN_00446040`

STC89C52RC/LE52RC（class 1）走 `FUN_00444110`，与 A2 已实现的 F002/6.6C 路径一致；这条路径的时钟/波特率参数已在 A2 实板验证。

## 时钟与容量分支

- `FUN_0043e7b0`：class 不是 `0xC8000`/`0xE0000` 时，用状态包第二测量样本 `+0x627/+0x628` 乘初始波特率再 `*12/7`；若 class > `0x167FFF` 改用另一组状态字节。F002 class `0x8000` 走前者，和 A2 观察一致。
- `FUN_004411c0`：class > `0xC7FFF` 时按选项字节分派 `FUN_0043e7b0`/`FUN_0043ed90`/`FUN_0043ef10` 等；F002 不进入该分支。
- `FUN_0043d530`：class 1–6、0x0F、0x10 用 6 MHz / 12 MHz 分档返回 `0x83`/`0x82`；其他 class 有更细的分档。F002 在第 1 档，11.03 MHz → `0x82`，与 A2 参数一致。

## 容量字段的观察（不是支持列表）

全表统计（1345 条）：

- `f3` 常见值：0x4000/0x2000/0x8000/0xC000/0x1000/0xF000/0x800/0xA000…，与型号后缀的 K 数并非简单相等（570 个带 K 后缀的记录中只有 4 个 `f3 == K*1024`），说明它是地址上限/保留区调整值，不是标称容量。
- STC89 子族的 `f3 + f4` 在同一子族内恒定：89C51/52/53/14 为 `0x3800`（如 89C52RC：`0x2000 + 0x1800`）；89C54/58/510/512/514/516 为 `0xF800`（如 89C54：`0x4000 + 0xB800`）；RD+ 为 `0xF800`；STC89C516RD/LV516RD 为 `0x10000`。这支持“`f3` 程序区、`f4` EEPROM/数据区”的假设，但仍需代码使用点确认。
- `f5` 对经典 89 重复 `f3`，现代芯片多为 0；`f6` 对 89 为 `0x4000`、RD+/现代多为 `0x10000`、32G12K128 为 `0x20000`；`f7` 低字节参与 `FUN_0044e310` 的减法。三者的完整语义未确认。

## 结论与边界

1. 已确认：记录布局、名称指针、16 位识别 ID、`f0` 的 class/timer/protocol 位位置、class→协议族分派、F002 走 class 1 / `FUN_00444110`、A2 已验证的时钟路径。
2. 部分确认：`f3`/`f4` 与程序/EEPROM 容量相关，`FUN_0044e310` 有实际使用点；但不能把表中数值直接当成所有型号的可写容量，也没有把 `program_bytes` 填入目录。
3. 未知：`f5`/`f6`/`f7` 完整语义、备用 ID 的逐条匹配规则、不同 class 的选项字节布局、各协议族的命令/ACK。
4. 本表仍是识别目录，不是烧录支持表；只有 F002 / `66 43 FD` 通过 A2 实板验收。
