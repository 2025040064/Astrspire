- `tools/aicube-uart-readonly.js` 只读观察官方进程的 `CreateFileA/W`、`SetCommState`、`SetCommTimeouts`、`ReadFile`、`WriteFile`、`GetOverlappedResult`、`PurgeComm`、`CancelIo/CancelIoEx`、`ClearCommError`、`CloseHandle`。脚本不修改返回值、缓冲区、官方 EXE 或授权流程。`tools/capture_aicube_uart.py` 在可选 Frida 依赖可用后，附加到用户已打开的指定 PID，仅将目标 COM 口事件写入新建的私有 JSONL 文件，不自动运行官方程序或触发下载。
- 该脚本仅覆盖观察到的 Win32 API 路径。若官方程序使用 `ReadFileEx`、IOCP、其他完成 API、驱动私有接口或未被钩到的打开路径，日志不能宣称完整。异步提交事件与完成事件必须区分，不能把提交直接当作物理 UART 发送成功。

## 不可替代的证据

QX-STC ISP 的 VOFA 风格监视器只能独占打开一个 COM 口接收普通 UART，不能与官方程序同时占用 COM8，也无法看到官方工具的 TX。因此它不是本轮抓包工具。既有静态帧候选与模拟器 `SIM/` 日志同样不能写入“官方实机抓包”栏目。
