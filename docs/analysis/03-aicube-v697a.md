## 观察到的芯片表

REA/Ghidra 将目标识别为 x86 PE，发现 7473 个过程、5904 个已定义字符串（`ev_f35a840dea33a63e493922709e6cb67ceac78a0a623a9a0e6c56b49fd53bede0`）。识别函数 `FUN_0043dfc0` 从地址 `0x504450` 起逐条读取 32 字节记录：比较收到的 16 位型号字段与记录中两个候选 ID，并结合版本字段判定；它不是简单的型号字符串搜索（`ev_066363bcb6c3936c70fa7ca41011861aa4b8491041f4d664ba9e2adf56ce7f8c`）。

只读读取表字节与名称区，得到索引 0 的 `UNKNOWN`、索引 1–1345 的 **1345 个不同型号名称**，以及索引 1346 的全零终止记录（表字节 `ev_3faa8da828c131aee7ac39c62bc9a801729bd4c170e2df007f319f9687278090`；名称字节 `ev_8fca088a7edeb60e7f43dc2b749b85bcebe6271d74e43bef56884251bcc73044`）。完整名称及主/备用识别 ID 存在 `chip_catalog.py`。其中 `STC89C52RC` 在表中的原文是合并项 `STC89C52RC/LE52RC`，索引 1275，主 ID 候选 `0xF002`；不能仅据此断定实机 ID、Bootloader 方言或可写范围。

本表穷举的是**当前定位到的识别表**，不证明官方界面所有可选项都来自它，也不证明 AiCube 所有传输方式/芯片均在表中。记录另有多个数值字段，形式上与容量相关，但尚未追到 HEX 地址范围检查和擦写调用，故 `ChipDescriptor.program_bytes` 一律为 `None`。版本字节会影响匹配；28 条记录有备用 ID，且主 ID 存在两个重复值，因此不能仅按主 ID 唯一选择方言。
