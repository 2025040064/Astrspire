## 独立计算与逐帧结果

已捕获状态中的测量值为 `0x0A79 = 2681`。在已观察的 2400 / 8N1、F002、原始版本字段 `66 43 FD` 下：

1. `clock_hz = 2681 * 2400 * 12 // 7 = 11030400`。
2. 目标 115200 时，`clock_hz / (32 * baud) = 2.9921875`；正值半入舍入得到 `3`；16 位负数 reload 为 `FF FD`。
3. 高字节补码为 `00`；延时字段 `min(254, (256 - 0xFD) * 2) = 06`；初始等待字段 `clamp((2400 // 1200) * 20, 40, 250) = 28`。
4. 该测量时钟位于 `[6 MHz, 12 MHz)`，静态范围标记为 `82`。
5. 独立计算得到 probe `8F FF FD 00 06 28 82` 和 activate `8E FF FD 00 06 28`，与原始官方记录逐字节一致，没有把 `FF FD` 写死为所有时钟的参数。

速率候选表从静态函数读出，依次为 `921600, 460800, 230400, 115200, 57600, 38400, 28800, 19200, 14400, 9600, 4800, 2400, 1200`。类别 3 按除数至少 2、最大范围及约 ±1% 误差选速；本次最快可用值为 115200。

独立实现以整数算术做正值半入舍入，使用原单精度约 0.01 的阈值，并额外重新检查最终选中速率的误差；极端浮点边界并未证明与 x87 的所有舍入细节逐位等价。因此不把纯计算器扩展为全型号通用协商，不为异常测量值兜底猜参数。

## 新增接口与安全边界

`Stc89ReadOnlySession(transport, emit=..., wait_power_seconds=30, initial_baudrate=2400, sync_interval=0.05)`：

- 注入传输对象，构造时不打开设备；`run()` 自行打开 2400 / 8N1，再限时发送单字节 `7F` 并读状态。
- 暴露 `run()`、线程安全取消 `cancel()`、`state`、`progress`、`status`、`known_profile`、`error`。
- 已识别的未知 ID / 版本可显示，但不被标为烧录支持。状态仅支持当前 53 字节 sum8 结构，其他格式不会猜解析。
- 帧前噪声上限 256 字节、帧上限 1024 字节；帧头后的坏长度、坏校验、坏尾、状态零测量和多余帧均失败关闭。
- 单次读取最长 50 ms；超时、取消、端口占用、断线、适配器异常均收口；关闭失败不能报告成功。
- 最终不发送 `8F/8E/80/84/00/FF/82` 等命令；没有擦除、写入、修改选项或主动结束复位。
- “只读”不等于零 TX，也不保证 COM 驱动打开端口时不改变 DTR/RTS。GUI 必须说明这一点并由用户显式触发。全局端口租约由调用方获取和释放，引擎只负责传输的开关。

`Stc89DownloadSession(image, transport, emit=..., allow_erase=False, ...)`：

- 默认门禁在身份解析后、波特率命令之前阻止继续；没有 GUI 真实下载入口，也没有加入 `HARDWARE_DIALECTS`。
- 实验测试显式允许后才运行协商、5 次准备、擦除、128 字节写块和 FF/82 结束；严格限制 F002 / `66 43 FD` / 8 KiB / 初始 2400。
- 在擦除前一次性验证 HEX 范围、填充、块构造、波特率计划和传输缓冲区清空能力。`purge_buffers()` 与 TX `flush()` 严格区分。
- 只接受有帧校验保护的预期 ACK；擦除 ACK 核对长度、标记和芯片 ID，设备特有尾部不硬编码。
- 任何擦除后异常立刻停止，不自动重发擦除/写块，不发送结束序列掩盖故障，并提示重新上电；取消亦不再发送新命令。
- `VERIFYING` 在此只代表所有块 ACK 匹配；**没有全片回读，也没有虚构 FF/82 的结束 ACK**。
