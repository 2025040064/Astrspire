# Project entry

Read the dev2 section of `docs/TASK_V060.md`, `docs/validation-v060-dev2.md` and `docs/architecture.md` before continuing. The current scope is the existing STC89C52RC programmer, serial assistant and basic software oscilloscope. Dev2 replaces waveform rendering with PyQtGraph and adds shared read-only NumPy arrays and selected-window measurements; it keeps schema6. Stable command-library references/templates, schema7, triggers, single capture, automatic frequency measurement and additional chips are outside this stage. Older one-hour/no-test instructions are superseded.

Only the existing F002 / 66 43 FD hardware fingerprint is enabled for STC programming; the chip catalog is not a supported-programming list. STM32 uses the data-debugging workspace, not a flashing interface. Read `docs/safety.md` and the latest `docs/hardware-v060-dev2.md` before any serial, capture or hardware action. Read `docs/REA_SETUP_FOR_CLAUDE.md` only when REA installation/connection needs attention; reuse working tooling.

Current baseline: shared raw sample history, asynchronous recording, stable-ID dashboards and command groups, schema6 (read schemas1–5), selected-card plotting tools, full card settings, per-card control editing/image export, explicit analysis sources, detailed native-import diagnostics, and independent CSV/JPG Demo. Check the release report for actual test/build results rather than reusing historical counts. Preserve old executables, workspace files and reports. Source changes require proportional offline tests; defect fixes require a failing regression first.

Software acceptance precedes separate hardware acceptance. On 2026-10-25, the user authorized connected-board tests: COM9 identification returned F002/6.6C; COM7 opened at the historical 115200/8N1 setting but received zero bytes in ten seconds. These are not fresh programming/streaming acceptance results. There is still no STC recovery HEX: identification only, no erase/write this round. Preserve the existing STC core/fingerprint. STM32 flashing remains out of scope; a future authorized flash requires identity, full backup and verified restoration, stopping on unreadable/protected devices. Native VOFA Qt5 DLL/QML ABI, unsupported native page/command structures, full 3D/effects/terminal semantics remain outside this version. Use independently written code/resources; no complete-equivalence claims.

Keep all controllable build, cache, runtime and log writes on drive F. This file does not authorize new hardware writes by itself.

Hard rule: never create development, build, test, temporary, cache or log files on drive C. Application runtime data also stays on drive F under `<install_root>\data`. Use the task folder on drive F, set `TEMP`/`TMP`/`PYINSTALLER_CONFIG_DIR` explicitly, and see `docs/NO_C_DRIVE.md` for the scope, exceptions and current paths.
